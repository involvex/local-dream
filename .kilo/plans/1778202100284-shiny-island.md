## Why

## Key facts to include

### Build System & Dependencies
- **Two separate build systems**: Gradle (Android/Kotlin) + CMake (native C++)
- **QNN SDK hard dependency**: Required at `/data/qairt/2.39.0.250926` (Linux path). The CMake build will fail without it.
- **Native build outputs**: `libstable_diffusion_core.so` (to `app/src/main/jniLibs/arm64-v8a/`) and QNN libraries (to `app/src/main/assets/qnnlibs/`)
- **Build scripts**: `app/src/main/cpp/build.sh` (Linux/macOS) and `app/src/main/cpp/build.bat` (Windows) - these orchestrate CMake and copy artifacts
- **Order matters**: Native build must complete BEFORE Gradle build, otherwise the APK won't include the native library
- **Git submodules**: Many 3rdparty libraries are git submodules that must be initialized (`git submodule update --init --recursive`)
- **ABI limitation**: Only `arm64-v8a` supported (not x86_64 or armeabi-v7a)

### Architecture
- **Separate process model**: The native `libstable_diffusion_core.so` is launched by `BackendService` as a separate process, not via JNI directly
- **HTTP API**: Native binary runs an HTTP server on `127.0.0.1:8081` (using cpp-httplib)
- **Communication**: Kotlin uses OkHttp to talk to the backend (tokenize, generate, health check endpoints)
- **Two execution modes**: NPU (QNN) and CPU (MNN) based on model type
- **Product flavors**: `basic` (no NSFW filter) and `filter` (includes `safety_checker.mnn`)
- **Model storage**: `app/src/main/assets/qnnlibs/` (packaged) and `filesDir/models/` (downloaded user models)
- **Patch system**: Resolution-specific `.patch` files (zstd-compressed) for SD1.5 models to enable non-512×512 resolutions

### Developer Commands
- **Initialize submodules**: `git submodule update --init --recursive`
- **Build native (Linux/macOS)**: `cd app/src/main/cpp && ./build.sh`
- **Build native (Windows)**: `cd app/src/main/cpp && .\build.bat`
- **Build Android APK**: `./gradlew assembleBasicDebug` or `./gradlew assembleFilterDebug`
- **Full build (assuming native already built)**: `./gradlew clean assembleBasicDebug`
- **Install to device**: `adb install -r app/build/outputs/apk/basic/debug/LocalDream_armv8a_2.4.3.apk`
- **Run tests**: `./gradlew test` (unit) and `./gradlew connectedAndroidTest` (instrumented, requires device)
- **Signing**: Release builds need `RELEASE_STORE_FILE`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD` in `gradle.properties` or environment

### Configuration & Paths
- **QNN SDK path in CMake**: Hardcoded to `/data/qairt/2.39.0.250926` (line 8 of `app/src/main/cpp/CMakeLists.txt`) - likely needs adjustment per developer machine
- **SampleApp patch**: `app/src/main/cpp/SampleApp.patch` applied automatically during CMake configure
- **Android NDK path**: Expected at `/data/android-ndk-r28` (in `CMakePresets.json`), uses `ccache` if available
- **Gradle JDK**: Java 17 required (set in `gradle.properties` and `app/build.gradle.kts`)
- **Android SDK**: `compileSdk=36`, `targetSdk=36`, `minSdk=28`
- **Native library directory**: `applicationInfo.nativeLibraryDir` (standard Android location for bundled native libs)
- **Cache invalidation**: If native libs don't update, clean with `./gradlew clean` and delete `app/src/main/jniLibs/` and `app/src/main/assets/qnnlibs/`

### Model & Chipset Details
- **Chipset detection**: Uses `Build.SOC_MODEL` (Android S+) to determine NPU capability
- **Suffix mapping**: Snapdragon chips mapped to model suffixes (e.g., SM8550→"8gen2", SM8450→"8gen1", generic SM→"min")
- **SDXL support**: Only for Snapdragon 8 Gen 3 and newer (SM8750, SM8850, SM8650, etc.)
- **Model files**: Expected file structure in `filesDir/models/<modelId>/` includes `unet.bin`/`.mnn`, `clip.bin`/`.mnn`, `vae_decoder.bin`/`.mnn`, `tokenizer.json`, optional `vae_encoder.bin`/`.mnn`, and `.patch` files for upscaling
- **Version marker**: NPU models have a `v3` file to track version (for upgrade detection)

### Testing & CI
- **Unit tests**: Standard JUnit 4 in `app/src/test/java/` (very minimal, example only)
- **Instrumented tests**: AndroidX Test in `app/src/androidTest/java/` (requires device/emulator)
- **No CI/CD**: No GitHub Actions workflows found
- **No pre-commit hooks**: No pre-commit config at repo level

### Gotchas & Quirks
- **QNN SDK path is hardcoded**: Developers must edit line 8 of `app/src/main/cpp/CMakeLists.txt` to match their QNN SDK installation, or set up a symlink at that path
- **Native build copies to assets and jniLibs**: The build scripts handle copying; don't manually move files
- **Gradle doesn't auto-trigger native rebuild**: Changing C++ code requires manually re-running the CMake build script first
- **Filter flavor includes NSFW checker**: `safety_checker.mnn` is copied from assets only when `BuildConfig.FLAVOR == "filter"`
- **Model downloads**: Happens via foreground service; requires `POST_NOTIFICATIONS` permission on Android 13+
- **Storage permissions**: Legacy external storage logic for pre-Android 10
- **Dynamic QNN loading**: Uses `DynamicLoadUtil` from QNN SampleApp to dlopen backend `.so` files at runtime

### Repo Structure
- Single-module Gradle project (`:app`)
- Monolithic C++ build combining all 3rdparty libs into one executable
- `app/src/main/cpp/3rdparty/` contains git submodules; `SampleApp/` is populated from QNN SDK at build time
- `app/src/main/assets/qnnlibs/` - QNN runtime libraries (gitignored, built by native build)
- `app/src/main/jniLibs/arm64-v8a/` - native executable (gitignored, built by native build)
- `app/src/main/assets/safety_checker.mnn` - only for `filter` flavor (gitignored? Actually tracked as it's in assets dir but only used in filter)

### Style & Conventions
- Kotlin code style: `official` (from gradle.properties)
- Jetpack Compose UI, Material 3
- Uses OkHttp for network, Coil for image loading
- StateFlow/StateFlow for reactive UI state
- Foreground services with notification channels for long-running tasks (model download, backend generation)
